# 문제 정의서 — 웹소설 장면 묘사를 원하는 포즈의 웹툰 컷으로 만들기

> N021 Main Quest 2 "내 도메인에서 AI로 개선 지점 찾아서 PoC 만들기" 제출용.
> [pose-image-tool](../pose-image-tool)(N017 챕터8 과제)에서 검증한 ControlNet Pose 기술을 실제 도메인 문제로 확장한다.

## 도메인 설명

웹소설·웹툰 등 스토리 콘텐츠를 기획하는 도메인이다. 특히 웹소설 원작을 웹툰으로 전환(2차 제작)하는 과정에서는, 글로만 쓰인 장면을 그림으로 옮기기 위해 **원작자와 웹툰 작가가 장면의 자세·구도를 맞추는 협업**이 반드시 필요하다.

## 현재의 문제

- 원작자는 장면을 텍스트로만 표현하고, 웹툰 작가는 그 텍스트를 읽고 상상해서 콘티(스토리보드)를 그린다.
- 원작자가 특정 포즈·구도를 명확히 전달하려면 말로 길게 설명하거나, 비슷한 레퍼런스 사진을 따로 찾아 전달해야 한다.
- 이 과정에서 소통 시간이 걸리고, 완성된 그림이 원작자가 머릿속에 그렸던 장면과 다르게 나오는 경우도 잦다 — 특히 "몸의 방향·팔다리 배치" 같은 구체적 자세는 텍스트만으로는 정확히 전달되지 않는다.

## 개선 가설

참조 포즈 사진(또는 원작자가 직접 취한 포즈 사진) + 장면 묘사 프롬프트를 함께 넣으면, **ControlNet Pose**가 그 포즈 그대로 원하는 캐릭터·배경·스타일의 웹툰풍 컷을 생성해준다. 원작자는 이 결과물을 "이런 느낌의 컷"이라는 시각 자료로 웹툰 작가에게 미리 전달할 수 있고, 이는 텍스트만으로 설명하거나 포즈를 지정하지 않고 생성한 결과보다 원작자의 의도(포즈·구도)를 훨씬 정확하게 재현한다.

## 대상 사용자

- 웹소설 원작자 (본인 포함)
- 웹툰화를 담당하는 작가·PD — 원작자의 의도를 빠르게 파악해야 하는 쪽

## 성공 기준 (정성 비교)

동일한 장면 프롬프트를 아래 두 조건으로 각각 생성해, 결과 이미지를 나란히 놓고 비교한다.

1. **조건 A (기존 방식 시뮬레이션)** — 포즈 지정 없이, 텍스트 프롬프트만으로 이미지 생성 (ControlNet 미사용). "말로만 설명해서 상상해 그리는" 현재 방식에 해당.
2. **조건 B (개선안)** — 같은 텍스트 프롬프트 + 참조 포즈 사진을 ControlNet Pose로 함께 입력.

**성공 조건**: 3개 이상의 서로 다른 포즈·장면 세트에서, 조건 B가 조건 A보다 "원작자가 의도한 자세(관절 위치·몸의 방향·팔다리 배치)"를 명확히 더 정확하게 재현한다. 각 세트마다 무엇이 달라졌는지 구체적으로 서술하고, 조건 B에서도 재현이 안 된 실패 사례(있다면)를 함께 기록한다.
