## 5. 빌드 (노트 4-4·4-5절)

사용자가 직접 `npx eas-cli@latest build --profile preview --platform android` 실행(서명 키 질문에 대화형으로 답해야 해서).

| 터미널 출력 | 뜻 |
|---|---|
| `Environment variables loaded from the "preview" build profile "env" configuration: EXPO_PUBLIC_API_URL` | 빌드용 주소는 `eas.json`의 `env`에서 읽힘(노트 3장의 규칙대로) |
| `No environment variables … found for the "preview" environment on EAS` | EAS 웹에 따로 등록한 값은 없다는 뜻. 문제 아님 |
| `No remote versions are configured … Initialized versionCode with 1` | `appVersionSource: remote`라 versionCode를 처음 만듦 |
| `Using remote Android credentials (Expo server)` → `Generate a new Android Keystore? yes` → `Detected that you do not have keytool installed locally.` → `Generating keystore in the cloud… Created keystore` | 서명 키를 **클라우드에서** 만들고 Expo가 보관. 노트북에 키 파일 생성 안 함 [확인] |
| `Compressed project files 1s (1.1 MB)` → `Uploaded to EAS 1s` → `Computed project fingerprint` | 업로드 |
| `Current phase Run gradlew` | 컴파일 중 |

`eas build:list`(완료 후): 상태 **finished**, 플랫폼 Android, 프로필 preview, 배포 internal, **SDK 58.0.0**, 버전 1.0.0(코드 1), 커밋 83c9aef, 시작 10:38:07 → 종료 10:57:15 = **19분 8초**, 결과물은 `.apk` [확인]. 대기열은 거의 없었다(업로드 직후 gradlew 단계) [추론].

- 무료 플랜 월 빌드 횟수를 **1회** 썼다.
- 이 빌드는 **커밋하지 않은 `app.json`·`eas.json` 변경을 포함한다**(결과 커밋 표시는 83c9aef 그대로) [추론: 업로드된 파일 1.1 MB가 작업 폴더 기준으로 보임 — 확인하지 않음].

## 6. 폰 설치와 독립 실행 확인 (노트 4-6절)

| 한 일 | 결과 |
|---|---|
| 설치 | 폰 카메라로 QR을 찍어 빌드 페이지 → 설치 링크 → 사용자가 설치 [사용자 보고: "설치했어"] |
| 터미널 | 빌드가 끝나자 터미널에 `Install and run the Android build on an emulator? (Y/n)`가 떠 멈춤 → 에뮬레이터가 필요 없어 **n/Ctrl+C**로 끔. 빌드·앱에는 영향 없음 |
| 대화 | 사용자가 "안녕 폰에 앱을 설치하고 처음으로 써봐"라고 보내자 "안녕! 앱 처음 써보는 거구나. 어떤 기능이 궁금해?"라는 답이 옴 [사용자 보고] → 설치 앱이 staging 백엔드와 직접 통신함 |
| 카메라 | 카메라 찍기를 누르자 권한을 요구했고, 찍은 사진의 글씨를 인식함 [사용자 보고] |
| 앱 권한 목록 | **허용됨: 카메라** / "앱이 계속 작동하도록 허용됨: 근처 기기" / **허용되지 않음: 마이크** [사용자 보고] |

**클리어 조건의 빈칸**: 대화 시험을 할 때 노트북 개발 서버가 꺼져 있었는지 사용자에게 물었지만 답을 받지 못했다. 이 세션에서는 개발 서버를 켠 적이 없다 [미확인 — 사실상 꺼져 있었을 것으로 추론].
이 밖에 확인하지 못한 것: 홈 화면의 앱 이름이 "대진이의 하루친구"인지, 처음 열 때 새 게스트로 시작해 캐릭터 화면부터 나왔는지, "출처 모름" 허용·Play 프로텍트 경고가 어떻게 보였는지.

**마이크 선언의 원인(코드로 확인)**: `node_modules/expo-image-picker/plugin/build/withImagePicker.js`는 `microphonePermission !== false`이면 `android.permission.RECORD_AUDIO`를 넣는다. `app.json`의 이미지 피커 플러그인에는 이 값이 없고 카메라 플러그인에만 `false`가 있었다. 즉 4절의 `permissions` 배열과 **별개로** 마이크가 선언됐다. 사용자가 허용하지 않으면 동작하지 않으나, 쓰지 않는 선언이다. 고치려면 이미지 피커 플러그인에 `"microphonePermission": false`를 넣고 **재빌드**해야 해서(빌드 1회) 이번에는 고치지 않고 점검표에 기록만 했다(사용자 선택). "근처 기기"가 어느 라이브러리에서 왔는지는 조사하지 않았다.

## 7. 출시 준비 점검표 (노트 5-6절)

`friend-agent-mobile/docs/store-readiness.md`를 만들었다(7개 항목 + 데이터 경로 표 + 설치 앱 사실 + 다음 과제). 코드를 읽어 확인한 사실:

- 데이터 삭제: 백엔드 `DELETE /api/data`·`/api/memories`·`/api/reminders/{id}`는 있고 앱 화면에는 없음. 게스트 계정 자체를 지우는지는 확인 못 함.
- AI 신고: 백엔드 `POST /api/report`(사유 300자, 관측 도구 점수로 기록)와 `/api/feedback`은 있고 **앱 화면에는 없음**. 앱 소스에서 "AI" 표시 문구도 찾지 못함.
- 결제: 백엔드에 토스페이먼츠 크레딧 결제(`/api/products`·`/api/orders`·`/api/payments/confirm`, N056)가 있음.
- 데이터 경로: 대화 → 내 백엔드·DB와 외부 LLM(`LLM_PROVIDER`, 기본 OpenAI), **대화 원문은 Langfuse에도 감**(이메일·카드·전화번호 패턴은 가림). 사진은 `/api/ocr`로 내 백엔드에, 글자 읽기는 코드상 백엔드 tesseract가 함. 로그인 정보는 기기 AsyncStorage.
- 못 본 것: 시스템 프롬프트가 사람 사칭을 막는지, 사진을 서버에 저장하는지.
