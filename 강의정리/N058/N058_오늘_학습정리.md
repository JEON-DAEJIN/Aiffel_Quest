# N058 오늘 학습 정리 — 시범 매장에서 진짜 매장으로, 그리고 개업 신고서의 빈칸

> 버전 v1.0 · 2026-11-06 · 강의 N058 「Expo 앱 빌드하고 출시 준비하기」와 오늘 실습을 내 방식으로 한 장에 정리했다. 28년 기획·경영 경험에 빗대 쓰고, 사실은 오늘 실습 진행기록에서 가져왔다.

## 오늘의 한 문장

> 📌 **요약** — Expo Go는 **개발 서버가 있어야 도는 시범 매장**이고, preview 빌드는 **코드를 앱 파일 안에 고정해 혼자 서는 진짜 매장**이다. 그런데 매장을 여는 데 가장 큰 변수는 앱이 아니라 **본사(백엔드)가 살아 있는가**였고, 스토어에 올리려면 앱 기능보다 **사용자 보호 장치(삭제·신고·AI 표시·개인정보방침)**의 빈칸을 메워야 한다.

## 1. 경영 경험으로 풀면

| 오늘 배운 것 | 경영에 빗대면 |
|---|---|
| **Expo Go → preview 빌드** | **시범 매장 → 정식 개점.** 시범 매장은 본사 직원이 옆에서 도와줘야 돌고, 정식 매장은 매뉴얼(코드)을 통째로 들고 혼자 선다 |
| **`eas.json`의 `env`** | **개점 서류에 적는 본사 연락처.** 개발 때 쓰던 메모(`.env`)는 본사 밖으로 못 나가므로, 개점 서류에 직접 적어야 한다 |
| **서명 키(클라우드 보관)** | **영업허가 도장을 금고(Expo)에 맡김.** 내 책상에 두지 않으니 잃어버릴 일은 적지만, 금고 열쇠(계정)가 곧 도장이다 |
| **패키지 이름** | **사업자등록번호.** 한 번 정하면 바꾸기 어렵다 |
| **결제 꺼짐으로 죽은 백엔드** | **본사 전기요금 미납으로 단전.** 매장을 아무리 잘 차려도 본사가 꺼지면 영업이 안 된다 |
| **`build:configure`가 넣은 마이크 권한** | **대행사가 개업 서류에 내가 안 쓰는 설비 신고까지 적어 넣음.** 제출 전에 서류를 다시 읽어야 한다 |
| **출시 준비 점검표** | **개업 전 인허가 체크리스트.** 인테리어(앱 화면)가 좋아도 환불 규정·위생 신고가 없으면 문을 못 연다 |

> 💡 **팁** — 비유의 한계: 개점 서류는 사람이 읽고 걸러 내지만, 도구가 자동으로 넣은 권한은 **조용히** 들어온다. 그래서 "도구가 무엇을 더했는지"를 `git diff`로 보는 습관이 필요하다.

## 2. 오늘 직접 해서 알게 된 것

1. **시작 전에 막힌 건 앱이 아니라 백엔드였다.** staging이 500이었고 원인은 결제 꺼짐이었다. 새 결제 계정을 연결해도 약 15분 503·429였다가, **새 리비전을 배포하자** 바로 살아났다.
2. **로그인은 터미널이 아니라 브라우저에서 끝난다.** 대기 중 터미널은 입력을 받지 않는 게 정상이다.
3. **설정을 만들어 주는 명령도 파일을 바꾼다.** `build:configure`가 프로젝트 ID 말고 마이크 권한까지 넣었다.
4. **서명 키는 클라우드에서 만들어졌다.** 로컬에 `keytool`이 없어도 된다.
5. **빌드는 19분 8초 걸렸고 무료 월 빌드 1회를 썼다.** 검사(`tsc`·`expo-doctor`)를 먼저 돌려 한 번에 끝냈다.
6. **설치한 앱이 노트북 없이 백엔드와 직접 대화했다**(사용자 보고). 카메라 권한도 뜨고 글자도 읽혔다.
7. **마이크는 두 군데에서 들어올 수 있었다.** 내가 지운 배열 말고도 이미지 피커 플러그인의 기본값이 있었다. 권한 목록에서 "허용되지 않음: 마이크"로 보였다.
8. **삭제·신고는 "없음"이 아니라 "API만 있음"이었다.** 백엔드는 이미 만들어 놨고 앱 화면이 없다. 대화 원문이 관측 도구(Langfuse)로도 간다는 것은 해설서 표에 없던 데이터 경로였다.

## 3. 오늘 틀린 것·고친 것

| 틀린 것 | 어떻게 알았나 | 고친 것·배운 것 |
|---|---|---|
| **(Claude) 결제를 연결하면 바로 살아날 줄 알았다** | 연결 뒤에도 503·429가 15분 이어짐 | 새 리비전을 배포해 깨움. 반영 지연인지 서비스 문제인지는 못 가림 |
| **(사용자) 로그인 대기 화면을 입력창으로 알았다** | "터미널에 입력할 수가 없어" | 브라우저에서 허용 화면을 눌러야 끝남 |
| **(도구) `build:configure`가 마이크 권한을 넣음** | `git diff`로 변경 확인 | `permissions` 배열을 지움 |
| **(Claude) 마이크를 다 막았다고 여겼다** | 설치 앱 권한 목록에 마이크가 있음 → 플러그인 코드를 읽음 | 이미지 피커 플러그인의 `microphonePermission` 기본값이 원인. 재빌드가 필요해 기록만 함 |

## 4. 이어 한다면(제안)

1. 설정 화면에 데이터 삭제 버튼 연결(API는 있음).
2. 답마다 AI 표시와 신고 버튼, 신고를 확인할 사람 정하기.
3. 개인정보처리방침 문서와 공개 URL.
4. 이미지 피커 플러그인에 `"microphonePermission": false` 후 재빌드.
5. 새 결제 계정 예산 알림 걸기.

## 5. 아직 모르는 것

- 결제 연결 뒤 15분 동안 503·429가 이어진 이유(반영 지연인지 서비스가 못 깨어난 것인지)
- 개발 서버를 끈 상태에서 시험했는지, 처음 열 때 새 게스트였는지
- "근처 기기" 권한이 어느 라이브러리에서 오는지
- 시스템 프롬프트가 사람 사칭을 막는지, 사진을 서버에 저장하는지

## 6. 가장 오래 막힌 곳

딱히 막힌 곳은 없었고, 빌드가 되는 동안 이게 제대로 되나 초초하게 기다린 것이 가장 막힌 곳이었음. 어제 해본 것들이어서 크게 힘든 부분은 사실 없었음.

- 대응하는 기록 [확인]: 빌드는 10:38:07에 시작해 10:57:15에 끝났다(19분 8초). 그동안 터미널은 `Run gradlew` 단계에서 진행 중이라고만 보였고, 중간에 알 수 있는 결과는 없었다. 이 대기는 학습서의 "시작하기까지 몇 분에서 수십 분, 시작한 뒤에도 10분 안팎"이라는 안내 범위 안이었다.
- 같은 날 막힌 것으로 보인 두 곳(결제 꺼진 백엔드, 로그인 대기 화면)은 사용자가 막힌 곳으로 꼽지 않았다. 앞의 3절 표에는 그대로 두었다.
