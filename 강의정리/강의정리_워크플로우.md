# 강의정리 워크플로우

예습에서 만든 두 문서가 학습 중 쌓인 기록과 합쳐져, 정리 단계에서 강의별 폴더로 자리 잡고, 실습·배포가 있는 강의는 보고서·방법론 문서·영상까지 이어지는 전체 흐름입니다. (2026-07-17 확정, 2026-10-21 3-5~3-8 추가)

---

## 1. 예습 단계 (동시 진행)

### 1-1. 학습서
LMS의 여러 챕터를 읽고 하나의 노션 페이지에 기록한다.

### 1-2. 해설서
각 챕터에 대해 AI를 활용하여 상세한 설명을 요청하고, 그 결과를 별도의 노션 페이지에 기록한다.

---

## 2. 학습 단계

수업이 진행되는 동안 수시로 기록한다. (**수업노트**)

- 오늘 배운 내용
- 수업 분위기 / 인상적인 장면
- 어려웠던 점 / 어떻게 극복했는지
- 새롭게 알게 된 점
- 오늘의 성장도 (1~5점 척도)
- 한줄 느낌 또는 내일의 각오
- 기타 에피소드

---

## 3. 정리 단계 — 모든 강의 공통

### 3-1. 강의노트 생성
클로드 코드(`/강의기록`)로 학습서와 해설서를 합쳐 **강의노트**를 생성한다 (md, html, word 3종 — 부록 A~G 포함, 양식 계속 업데이트 중).

### 3-2. 수업노트 정리 `(양식 논의 필요)`
수업노트를 체계적으로 정리한다. 세부 양식은 추후 클로드 코드와 다시 논의한다.

### 3-3. 폴더 배치
정리된 폴더는 `강의정리` 폴더 안에 강의 순서에 따라(예: `N008`) 배치한다.

```
강의정리/
├─ N008/              # 강의 순서별 폴더
│   ├─ N008_..._학습서.pdf
│   ├─ N008_..._해설서.pdf
│   ├─ N008_주제명(키워드).md / .html / .docx   ← 강의노트(3-1)
│   ├─ (실습 있으면) N008_실습과제_제출보고서.md / .html / .docx   ← 3-5
│   └─ (재사용 방법론 있으면) 방법론 문서 사본.md / .html / .docx   ← 3-6, 원본은 프로젝트 폴더에
└─ N009/
    └─ ...
```

### 3-4. 클라우드 보관 `(자동화 논의 필요)`
정리된 노트를 구글 드라이브와 깃허브에 백업한다. N044부터는 `Aiffel_Quest` git 저장소에 매번 커밋한다(push는 매번 따로 확인).

## 4. 실습·배포가 있는 강의만 — 추가 4단계

**순수 개념 강의(실습 없이 설명만 있는 강의)는 이 네 단계를 만들지 않는다.** 억지로 만들면 알맹이 없는 문서가 된다는 게 이유다 (2026-10-21, N045~N047 폴더의 실제 상태를 점검하며 확정).

> 최종 확정된 전체 로직(사용자 확정 문구): 1. 학습서·해설서(입력, 그대로) → 2. 강의노트 3종(`/강의기록`) → 3. **(실습·배포가 있는 강의만)** 보고서 3종 + 방법론 문서 3종(재사용 원리가 있을 때만) → 4. Motion 영상(선택, 원하실 때) → 5. 노션 업로드.

### 3-5. 실습과제 제출보고서 `[항상 만든다]`
- **이름은 반드시 `N0XX_실습과제_제출보고서`로 통일** — md/html/docx **3종**. 노션엔 md 내용을 그대로 복붙하면 되므로 "설명서" 같은 별도 포맷·이름은 쓰지 않는다.
- ⚠️ **실제로 한 번 어겼던 실수**: N047에서 처음에 `N047_실습과제_설명서`라는 이름으로 md만 만들었다가, N046과 포맷·이름이 안 맞아 나중에 html·docx를 보강하고 이름도 `제출보고서`로 다시 맞춘 적이 있다(2026-10-22). → **새 N0XX 폴더가 생기면 이름부터 먼저 확인한다.**
- "이번에 실습을 실제로 했다"는 **수행 기록이자 증거**. 제출용이든 동료 평가용이든 목적·형식은 같다.
- **양식 — N049부터(2026-10-23 확정): 노션 「강의정리 양식」 구조.** 한눈에 읽는 8쪽 안팎으로 쓴다. 구성: `0. 한눈에`(도형 하나 + 한 줄 요약 + 실제로 센 숫자) → 교재 장·단계 순 절(절마다 한 일 + **"교재와 다르게 한 것"** + 막혔던 일) → **사고·문제 표**(변경 | 결과 | 사용자에게 보였을 것 | 원인을 찾은 곳 | 처리) → **풀지 못한 것 · 교재와 달라진 것** → 정리 → 궁금했던 것(Q&A) → 평가 체크리스트(제출용) → 첨부할 증거 화면 목록. 그림은 "표·도형으로 만들 수 있는 것"은 문서 안에 넣고, 캡처가 필요한 것은 증거 화면 목록으로 남긴다.
- **상세 기록은 부록으로 분리**: 명령·로그·수치를 있는 그대로 담은 긴 기록은 `N0XX_실습과제_제출보고서_부록_상세기록` md/html/docx 3종으로 둔다(N049는 기존 11쪽 보고서를 그대로 보존). 본문은 부록 파일을 가리킨다.
- **소급하지 않는다**: N045~N048의 보고서는 이전 양식(한 장 요약 표 → 단계별 수행 내용 → 핵심 교훈 → 한계 → 평가 체크리스트 → 증거 화면) 그대로 둔다. 이전 양식의 대체 이유: 같은 독자·같은 사실·같은 노션 용도인데 새 양식이 절반 이하 분량으로 훑어보게 하고, "풀지 못한 것"과 평가 체크리스트는 새 양식에 흡수했다.

### 3-6. 방법론 실전적용 문서("매뉴얼") `[재사용 가능한 일반 원리가 나올 때만]`
- 보고서(3-5)와는 **독자·목적·수명이 다른 별개 문서**다 — 보고서=시간순 기록이자 증거, 방법론 문서=다음에 또 쓸 레시피.
- 형식: "일반 원리 → 실제 적용 예시 → 체크리스트 → 용어 사전" (예: `AI_기능을_서비스로_설계하는_법(N045_방법론_실전적용).md/html/docx`).
- **원본은 그 방법론을 실제로 적용한 프로젝트 폴더**(예: `projects/AI-Story-Partner/docs`)에 두고, **강의 폴더(`강의정리/N0XX`)에는 사본**을 둔다.
- 여러 강의가 같은 서비스·프로젝트를 이어서 다루면(N046→N047처럼) 문서를 쪼개지 말고 **한 편으로 묶어 양쪽 강의 폴더에 같은 사본**을 둔다.
- 아직 코드·실행 이력이 없는 프로젝트에 적용할 계획을 적을 땐 "계획"이라고 분명히 표시하고 실제 한 일처럼 쓰지 않는다.
- **만들지 "애매하면 먼저 사용자에게 묻는다"** — 모든 실습 강의에 무조건 만드는 게 아니라, "다음에 재사용할 만한 일반 원리가 실제로 나오는가"를 먼저 판단한다.

### 3-7. Motion 영상 `[선택 — 원할 때만]`
- Claude Motion(또는 동급의 코드 기반 애니메이션)으로 그날 실습을 10~30초 안팎으로 요약하는 mp4를 만든다.
- **매번 필수는 아니다.** 사용자가 원할 때만 만든다.
- **원본은 방법론 문서(3-6)와 같은 프로젝트 폴더에, 사본은 강의 폴더에** 둔다(예: `AI-Story-Partner/docs/N047_실습_모션요약.mp4` + 소스 `.html`, 강의 폴더엔 사본).

### 3-8. 노션 업로드
- 위 산출물(보고서·방법론 문서·영상)을 사용자가 쓸 노션 페이지에 붙여넣기 좋은 형태로 정리해 전달한다.
