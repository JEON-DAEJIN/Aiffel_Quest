Lecture Organization Workflow

강의정리 워크플로우

예습에서 만든 두 문서가 학습 중 쌓인 기록과 합쳐져 강의별 폴더로 자리 잡고, 실습·배포가 있는 강의는 보고서·방법론 문서·영상까지 이어지는 흐름입니다. (2026-07-17 확정, 2026-10-21 3-5~3-8 추가)

1

예습 단계

LMS 챕터를 두 갈래로 동시에 읽고 기록한다

1-1

학습서

LMS의 여러 챕터를 읽고 하나의 노션 페이지에 기록

1-2

해설서

각 챕터를 AI에게 상세 설명 요청 → 별도 노션 페이지에 기록

동시 진행
2

학습 단계

수업이 진행되는 동안 수시로 기록한다

↻ 수업 중 수시 기록

수업노트

  • 오늘 배운 내용
  • 수업 분위기 / 인상적인 장면
  • 어려웠던 점 / 극복 방법
  • 새롭게 알게 된 점
  • 오늘의 성장도 (1~5점)
  • 한줄 느낌 또는 내일의 각오
  • 기타 에피소드
3

정리 단계 — 모든 강의 공통

두 문서와 기록들을 강의노트로 합치고, 폴더 체계에 맞춰 보관한다

3-1

강의노트 생성양식 계속 업데이트

클로드 코드로 학습서 + 해설서를 합쳐 강의노트 생성 (md / html / word)

3-2

수업노트 정리양식 논의 필요

학습 단계에서 쌓인 수업노트를 체계적으로 정리

3-3

폴더 배치

강의 순서 폴더와, 4종 문서만 모으는 아카이브 폴더를 분리 관리

강의정리/ ├─ N008/ # 강의 순서별 폴더 │ ├─ 학습서.md │ ├─ 해설서.md │ ├─ 강의노트.md / .html / .docx │ └─ 수업노트.md ├─ N009/ │ └─ ... └─ 모음/ # 문서 종류별 아카이브 ├─ 학습서/ ├─ 해설서/ ├─ 강의노트/ └─ 수업노트/
3-4

클라우드 보관자동화 논의 필요

정리된 노트를 구글 드라이브와 깃허브에 백업. N044부터는 Aiffel_Quest 저장소에 매번 커밋(push는 매번 확인)

4

실습·배포가 있는 강의만 — 추가 4단계

순수 개념 강의는 만들지 않는다 — 억지로 만들면 알맹이 없는 문서가 된다

최종 확정 로직: 1. 학습서·해설서(입력) → 2. 강의노트 3종 → 3. (실습 있는 강의만) 보고서 3종 + 방법론 문서 3종(재사용 원리 있을 때만) → 4. Motion 영상(선택) → 5. 노션 업로드
3-5

실습과제 제출보고서 항상 만든다

이름은 반드시 N0XX_실습과제_제출보고서로 통일, md/html/docx 3종. 노션엔 md를 그대로 복붙하면 되므로 "설명서" 같은 별도 이름은 쓰지 않는다.

실제로 한 번 어겼던 실수 — N047에서 처음엔 N047_실습과제_설명서로 md만 만들었다가, N046과 이름·포맷이 안 맞아 나중에 html·docx를 보강하고 이름도 다시 맞춘 적이 있다(2026-10-22). 새 N0XX 폴더가 생기면 이름부터 먼저 확인한다.
3-6

방법론 실전적용 문서("매뉴얼") 재사용 원리가 있을 때만

보고서(3-5)와는 독자·목적·수명이 다른 별개 문서 — 보고서=기록·증거, 방법론 문서=다음에 또 쓸 레시피. 형식: 일반 원리 → 실제 적용 예시 → 체크리스트 → 용어 사전. 원본은 그 방법론을 실제 적용한 프로젝트 폴더에, 강의 폴더엔 사본만 둔다. 여러 강의가 같은 서비스를 이어 다루면(N046→N047) 한 편으로 묶어 양쪽에 같은 사본을 둔다.

3-7

Motion 영상 선택 — 원할 때만

그날 실습을 10~30초 안팎으로 요약하는 mp4. 원본은 방법론 문서와 같은 프로젝트 폴더에, 사본은 강의 폴더에 둔다.

3-8
