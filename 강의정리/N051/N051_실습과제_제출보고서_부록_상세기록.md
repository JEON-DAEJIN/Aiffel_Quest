## 6. 정리 정책 드라이런

`docs/cleanup-policy.json`(작업 폴더의 git 미추적 파일. 처음 만든 로컬 브랜치 `cleanup-policy`는 파일을 커밋하지 않았고 비어 있어 삭제했다):

```json
[
  {"name": "delete-older-than-7d", "action": {"type": "Delete"}, "condition": {"tagState": "any", "olderThan": "7d"}},
  {"name": "keep-recent-10", "action": {"type": "Keep"}, "mostRecentVersions": {"keepCount": 10}}
]
```

```bash
gcloud artifacts repositories set-cleanup-policies friend-agent --project <프로젝트 ID> --location us-central1 --policy docs/cleanup-policy.json --dry-run
gcloud artifacts repositories set-cleanup-policies cloud-run-source-deploy --project <프로젝트 ID> --location us-central1 --policy docs/cleanup-policy.json --dry-run
gcloud artifacts repositories describe <저장소> --project <프로젝트 ID> --location us-central1 --format="yaml(cleanupPolicyDryRun,cleanupPolicies)"
```

조회 결과(두 저장소 동일): `delete-older-than-7d`(action DELETE, `olderThan: 604800s`, `tagState: ANY`), `keep-recent-10`(action KEEP, `keepCount: 10`), **`cleanupPolicyDryRun: true`**. 저장소 크기: `friend-agent` 316.397MB, `cloud-run-source-deploy` 2217.921MB.

`cloud-run-source-deploy` 이미지 40개의 만든 시각(UTC)으로 시뮬레이션한 삭제 후보(7일 초과이면서 최근 10개 밖):

| 시점 | 7일 초과 | 저장소 전체 기준 삭제 | 이미지 이름별 기준 삭제 |
|---|---|---|---|
| 10-27 01:20Z(지금) | 0 | 0 | 0 |
| 10-28 01:20Z(내일) | 6 | 6 | 6 |
| 10-30 01:20Z(3일 뒤) | 20 | 20 | 16 |

크기 합계는 이미지끼리 겹치는 레이어를 중복으로 세므로 실제 확보 용량보다 크게 나와 표에서 뺐다. 감사 로그(`artifactregistry.googleapis.com`의 정리 관련 메서드)를 `--freshness=2d`로 조회했으나 기록이 없었다.

컨테이너 로그: {"severity": "ERROR", "message": "tesseract 프로그램을 찾을 수 없습니다. 실행 환경에 tesseract 가 설치되어 있지 않습니다."}

고장본과 `starter/Dockerfile`의 차이는 `RUN apt-get update && apt-get install -y --no-install-recommends tesseract-ocr tesseract-ocr-kor && rm -rf /var/lib/apt/lists/*`(주석 포함 5줄) 삭제. 복구본: `POST /api/ocr` = HTTP 200, `{"text":"산책 동아리 10월 일정\n10월 넷째 주 공지\n10월 21일 수요일 19:00 …`.

**문제 B**(`env-included/dockerignore`): `docker run --rm friend-agent:broken-b ls -a /app` 결과에 `.env`가 있었다(이 외 `.env.example`·`.gcloudignore`·`.github`·`.gitignore`·`AGENTS.md` 등). `.env` 내용은 열어 보지 않았다. 이미지는 어디에도 올리지 않았다. 원본(HEAD) 대비 차이:

```text
-.env
-**/__pycache__/
-**/*.pyc
+__pycache__/
+*.pyc
```

복구본의 `/app` 목록에는 `.env`가 없고 `.env.example`만 있었다. 로컬 폴더에서 git이 무시하는 파일: `.env`, `.pytest_cache/`, `.venv/`, `app/__pycache__/`, `app/store/__pycache__/`.

**문제 C**(`root-user/Dockerfile`): `/version`·`/health`(`{"status":"ok"}`, HTTP 200) 정상, `docker run --rm friend-agent:broken-c whoami` = **`root`**. 차이: 아래 3줄이 없음.

```text
# 5) 관리자(root)가 아닌 사용자로 실행한다.
RUN useradd --create-home appuser
USER appuser
```

복구본 `whoami` = `appuser`, `/health` = 200.

**문제 D**(`port-fixed/Dockerfile`): `docker ps`는 `0.0.0.0:8080->8080/tcp` `Up`, `curl http://localhost:8080/health` = `HTTP 000`(curl 종료 코드 52). 로그: `INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)`. 차이:

```text
-CMD ["sh", "-c", "uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8080}"]
+CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

복구본: 로그 `0.0.0.0:8080`, `/health` = 200. `-e PORT=9000 -p 9000:9000`로도 로그 `0.0.0.0:9000`, `/health` = 200.

고장본에는 이 외에 `starter/`와 현재 Dockerfile의 `poppler-utils`를 설치하는 `apt-get` 줄 1개(−/+ 한 쌍)의 차이가 항상 함께 나온다(고장본이 `starter/` 기준이라 문제 원인과 무관). 연습용 이미지는 모두 `docker image rm`으로 지웠고 컨테이너도 남기지 않았다. `git status`는 깨끗했다(미추적 `docs/cleanup-policy.json`만).
