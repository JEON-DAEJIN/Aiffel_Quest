### 4-5. 단계 5 — Dockerfile · 로컬 빌드

- `staging`에서 `add-dockerfile` 브랜치를 만들고 `starter/Dockerfile`과 `starter/dockerignore`를 복사했다. `.gcloudignore`는 이미 있었고 `.env`를 빼며 Dockerfile은 빼지 않는다
- **5기준 검토 5개 모두 통과**: 베이스 고정(`python:3.13-slim-bookworm`), `tesseract-ocr`+`tesseract-ocr-kor` 설치, `.dockerignore`에 `.env`, `${PORT:-8080}`, `USER appuser`. `Procfile`·`.python-version`(3.13)과 `FROM` 버전이 일치했다

Cloud Build 로그의 Step 1~9에서 복원한 Dockerfile 명령(주석과 빈 줄은 로그에 없어 뺐다)

```
FROM python:3.13-slim-bookworm
RUN apt-get update && apt-get install -y --no-install-recommends tesseract-ocr tesseract-ocr-kor && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
RUN useradd --create-home appuser
USER appuser
CMD ["sh", "-c", "uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8080}"]
```

**첫 빌드**: 이미지 `friend-agent:local` **460MB**(content 108MB)

| 레이어(Dockerfile 줄) | 교재 그림 | 이번 실측: 첫 빌드 | `.dockerignore` 수정 후(05a) |
| --- | --- | --- | --- |
| 베이스 이미지(`FROM`) | 약 225MB | 공식 이미지 단독 실측 183MB(단계 4) | (같은 베이스) |
| tesseract(apt) | 약 95MB | 94.9MB | 94.9MB |
| 라이브러리(requirements 복사+pip) | 약 89MB | 120MB | 120MB |
| 코드 복사(`COPY . .`) | 약 0.2MB | 442kB(.pyc 17개 포함 상태) | 266kB |
| useradd | 거의 0 | 69.6kB | 69.6kB |
| `CMD` | 0 | 0B | 0B |

- 교재 그림의 레이어 대응은 교재 원문 그림을 직접 열어 확인한 것이다
- pip 레이어가 교재(약 89MB)보다 120MB로 컸다. 원인은 설치된 패키지 버전 차이로 **추정**한다
- 코드 복사 레이어가 442kB에서 266kB로 줄어든 것은 .pyc 제거와 맞아 보이나 인과를 직접 측정하지는 않은 **추정**이다
- 레이어별 실측을 더한 값과 이미지 전체 460MB의 관계는 장부에 설명이 없어 합계를 계산해 쓰지 않았다
- 컨테이너 실행(`-p 8080:8080`, 환경변수는 `-e`)으로 같은 사진을 보내 200 · 153글자 · `e61b2db05f`(로컬과 같음). 이미지 안의 tesseract가 읽었다

**이미지 점검** (`docker run --rm friend-agent:local …`)

```
ls -a /app       → .dockerignore .env.example .gcloudignore .github .gitignore .python-version AGENTS.md CLAUDE.md
                   Dockerfile Procfile README.md app data pytest.ini requirements-dev.txt requirements.txt static

```

**함정**: 템플릿 `.dockerignore`의 `__pycache__/`와 `*.pyc`가 맨 위 폴더에만 적용돼 `/app/app/__pycache__`에 **.pyc 17개(모두 cpython-314, 내 PC의 .venv가 만든 것)**가 이미지에 들어갔다.

수정: 두 줄을 아래처럼 바꿨다.

```
**/__pycache__/
**/*.pyc
```

재빌드 결과: 이미지 안 `__pycache__` 0개 · `.pyc` 0개. 재빌드 단계에서 apt · WORKDIR · requirements 복사 · pip는 **CACHED**였고 `COPY . .`와 useradd만 새로 실행돼 전체 약 0.5초였다. 크기는 460MB 그대로이고 새 이미지로 OCR 200을 다시 확인했다.

도구 사정: Git Bash가 `/app` 인자를 윈도 경로로 바꿔 `ls -a /app`이 한 번 실패했고 `MSYS_NO_PATHCONV=1`로 해결했다(Docker 문제가 아님). 증거: `05a_local_image_inspect.txt`.

### 4-10. 과제 3(도전) — PDF 공지문 읽기(poppler)

**후보 비교와 선택**: PDF(poppler)를 선택했다. QR/zbar는 2순위, HEIC · ffmpeg는 비추천이었다. HEIC는 `pillow-heif` 휠이 libheif를 포함해 시스템 패키지가 필요 없을 수 있다(미확인), ffmpeg는 음성 인식 API까지 얽혀 난이도가 높다고 보았다.

## 8. 하지 않은 것 · 한계 (사실대로)

- **staging 서비스·수업 키 처리**: 이번에 다루지 않았다(N049 상태 그대로, 수업에서 받은 LLM 키를 staging·production이 공유하며 한도를 분리하지 못했다)
- **이미지 태그·digest 관리, 검증한 이미지를 그대로 승격하는 흐름, 저장 공간(400MB대 이미지가 배포마다 쌓임) 관리**: 교안이 "다음 실습"으로 남긴 숙제로 하지 않았다
- **며칠 간격 빌드로 패키지 버전이 달라지는 것**: 재현하지 않았다(이번 비교는 모두 몇 시간 이내 → 패키지는 같고 이미지 ID만 다름)
- **`--clear-base-image` 누락 오류**: 직접 재현하지 않았다
- **원격 브랜치 `origin/add-dockerfile`·`origin/add-pdf-ocr`**: 삭제하지 않고 남겼다
- **과제 1의 브라우저 직접 대화**: API로 대체했다
- **QR · HEIC · ffmpeg**: 후보로만 비교하고 구현하지 않았다
- **새 PDF 테스트**는 poppler 설치 여부를 검증하지 못한다(변환 함수를 가짜로 바꿈). 실제 확인은 컨테이너·staging 몫이다
- **두 번째 production 배포(PR #23)의 승인 화면**은 캡처하지 않았다
- **다른 프로젝트에 대한 적용**: 해설서가 제안한 다른 프로젝트 적용은 계획일 뿐 이번에 한 일이 아니다
