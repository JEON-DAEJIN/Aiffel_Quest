오늘의 한 문장

📌 요약 — 웹 서비스를 폰 앱으로 가져갈 때 새로 만드는 것은 화면과 기기 기능이라는 출입구뿐이고, 백엔드·데이터베이스는 API 모양을 그대로 둔 채 재사용한다. 그래서 백엔드를 고쳐도 앱은 다시 만들 필요가 없다. 그리고 AI의 말은 증거가 아니다. 서버가 실제로 한 일(메모·로그·데이터베이스)을 보고 판단한다.

1. 경영 경험으로 풀면

오늘 배운 것경영에 빗대면
같은 백엔드, 새 앱본사는 그대로, 새 매장 개점. 인테리어(화면)와 계산대(카메라)는 새로 들이지만 고객 장부와 업무 규정은 본사에 있다
Expo Go개점 전 시범 매장. 기본 설비는 다 있어 바로 열어 볼 수 있지만, 특수 설비(Expo Go에 없는 부품)는 들일 수 없다
기기마다 다른 손님회원 카드 없는 단골. 폰에서 온 손님과 노트북 브라우저에서 온 손님은 같은 사람이어도 장부상 다른 사람이다(폰 강아지 하루 / 브라우저 곰 하루)
입력창에서 사람이 고친 뒤 보냄(HITL)결재 전 담당자 검토. 스캔한 서류(OCR)를 그대로 결재하지 않고 담당자가 읽어 보고 고친 뒤 올린다
안전장치의 빈칸검토 담당자의 체크리스트. 목록에 없는 표기("11월 7일", "저장해 줘")를 만나자 신입(AI)이 맞게 쓴 서류를 반려했고, 엉뚱하게 고쳤을 가능성도 크다
메모가 증거결재 도장. 직원이 "처리했습니다"라고 말한 것과 도장이 찍힌 서류는 다르다
노트북 주소가 바뀌면 앱이 길을 잃음본사가 예고 없이 이사. 거래처(폰)는 옛 주소로 서류를 보내고 답을 기다린다

💡 팁 — 비유의 한계: 회사의 체크리스트는 사람이 들고 다니며 융통성 있게 쓰지만, 코드 안전장치는 목록에 없는 표현을 만나면 조용히 틀린다. 그래서 장치가 고치거나 뺀 이유를 기록에 남기고, 장치를 거치기 전과 후를 나눠 봐야 누가 틀렸는지 가릴 수 있다.

2. 오늘 직접 해서 알게 된 것

  1. 앱은 백엔드 주소 하나로 시작했다. 폰이 켜지면 설정 → 나는 누구 → 캐릭터 → 대화 순서로 백엔드를 불렀고, 교안의 시퀀스 그림과 순서가 같았다. 답은 글자 단위로 흘러왔다("스트리밍이야. 확실해").
  2. 앱을 껐다 켜도, 부품을 통째로 바꿔도 대화는 그대로였다. 대화는 백엔드의 데이터베이스에 있고, 폰에는 열쇠(로그인 토큰)만 있다.
  3. 같은 백엔드를 써도 기기마다 다른 손님이었다. 노트북 브라우저를 열자 예전 실습 때의 손님(곰 하루, 크레딧 30)이 나왔다. 데이터베이스의 사람 번호가 달랐다(9184e31a / 02604922).
  4. 실제 폰에서 입력해 봐야 보이는 문제가 있었다. Android 자판이 입력창을 가렸다. 교안 확인 목록에는 없었다.
  5. 카메라만 OCR이 안 됐을 때 범인은 업로드 함수가 아니었다. 사진첩은 되는데 카메라만 실패했고, 업로드 방식을 세 번 바꾼 뒤에야 찍은 사진 주소를 넘기는 방법이 달랐다는 것을 찾았다.
  6. OCR은 엔진보다 사진이 결과를 갈랐다. 손글씨는 거의 못 읽고, 화면을 찍은 사진은 깨지고, 인쇄물과 캡처는 정확했다. 그래서 읽은 글을 바로 보내지 않고 입력창에서 고치게 한 설계가 맞았다.
  7. AI가 완료했다고 답해도 아무 일도 안 일어날 수 있었다. 로그를 보니 도구를 하나도 쓰지 않았다(tools: []). 일정을 물었을 때도 장부를 보지 않고 대화 기억으로 답해 한 건이 빠졌다.
  8. 시험 220개가 통과하던 백엔드에서 빈칸 세 개가 나왔다. 달력 날짜를 몰라 하루 앞당겨 저장, "저장해 줘"를 부탁으로 몰라 빼 버림, 일정을 물어도 조회를 안 함. 백엔드만 고쳤고(시험 248개) 앱은 한 번도 다시 빌드하지 않았다.

3. 오늘 틀린 것·고친 것

틀린 것어떻게 알았나고친 것·배운 것
(템플릿) Android에 자판 처리가 없었다사용자 캡처 "타이핑하는 글자를 볼 수가 없어"두 플랫폼 모두 같은 처리. 강사님께 알릴 거리
(실험) 안내 문구 칸에 질문 문장을 넣었다 — 칸은 Claude가, 문장은 사용자가 골랐다사용자 "입력창에 … 계속 남아 있는 것도 문제"안내 문구에는 무엇을 하는 칸인지만 쓴다
(Claude, 자기평가) 카메라 실패를 업로드 함수 문제로 보고 세 번 바꿨다사진첩은 성공, 카메라만 실패, 백엔드엔 요청 0건한 경로만 실패하면 두 경로의 차이부터 본다
(Claude) 사진 올리기 오류 문구에 "백엔드 주소·와이파이 확인"이라고 써 두었다이번엔 요청이 폰 밖으로 나가지도 않았다오류 문구를 믿기 전에 서버에 요청이 왔는지 본다
(Claude) 원이 계속 돌 때 노트북 주소를 확인하지 않고 "다시 열어 풀렸다"로 넘어갔다다음 끊김에서 노트북이 다른 와이파이로 옮겨 타 있었다 — 첫 번째도 같은 원인이었을 가능성앱이 멈추면 폰 요청이 오는지와 노트북의 현재 주소부터 본다
(백엔드) 날짜·부탁 낱말·조회의 빈칸 세 개사용자 "그런데 이건 서버 문제인지" + 메모가 없는 답 + 데이터베이스 대조같은 말로 실제 모델을 다시 돌려 장치 전·후를 나눠 원인을 찾고, 시험을 더해 고쳤다
(사용자) 홈 폴더에서 npx expo start -c"expo@58.0.23 설치할까요?"가 뜸앱 폴더로 이동해 다시 실행. 터미널 맨 앞의 폴더 경로를 먼저 본다

4. 이어 한다면(제안)

  1. 백엔드 수정(n057-date-fix)을 웹 서비스에도 반영한다. 다만 이 브랜치에는 N056 크레딧 결제 커밋이 함께 있어, staging에 결제까지 올릴지 먼저 정한다.
  2. Cloud Run 결제를 켜면(사용자 결정) 공개 주소(https)로 앱을 연결해 콜드 스타트와 연결 문제를 다시 본다.
  3. 조회한 사실도 답 아래에 표시해, 장부를 보고 답했는지 화면에서 알 수 있게 한다.
  4. 지난 대화에도 메모가 보이도록 백엔드가 메모를 저장·반환하게 한다.
  5. 다른 사람 폰에 설치하려면 EAS Build로 앱 파일을 만든다(오늘 범위 밖).

5. 아직 모르는 것

  • 처음 문구를 바꿨을 때 왜 저절로 반영되지 않았는지(두 번째부터는 됐다)
  • 카메라 사진 주소가 화면 이동 주소로 넘어가며 정확히 어떻게 바뀌었는지(보관함으로 바꿔 해결했을 뿐 직접 확인하지 않았다)
  • 공개 주소(https)·콜드 스타트 환경에서 앱이 어떻게 보이는지
  • "알려 줘"에 모델이 도구를 안 고른 그 한 번의 이유(같은 말로 다시 돌리면 3번 모두 맞게 골랐다)

6. 가장 오래 막힌 곳

카메라 열기를 통해 손글씨를 인식하는 것이 가장 힘들었어.

인쇄된 다른 글씨는 잘 읽히는데 손글씨와 화면 모니터를 찍은 것은 잘 구분하지 못했어. 그래도 클로드와 대화를 통해 하나하나 변수를 바꿔가면 고쳐가는 과정이 재미있었어. 결과가 잘 나와 다행이야.
