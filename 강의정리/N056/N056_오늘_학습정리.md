# N056 오늘 학습 정리 — 메시지 한 건의 원가를 알고, 쓴 만큼 받고, 두 번 받지 않기

> 버전 v1.0 · 2026-11-04 · 강의 N056 「원가를 계산하고 크레딧 결제 붙이기」와 오늘 실습(1~8장)을 내 방식으로 한 장에 정리했다. 28년 기획·경영 경험에 빗대 쓰고, 숫자는 오늘 실습 진행기록에서 가져왔다(원 단위는 1,400원/달러 가정).

## 오늘의 한 문장

> 📌 **요약** — AI 서비스는 메시지마다 재료비가 나가고 그 비용은 **사용량에 비례**한다. 그래서 원가를 비싼 쪽까지 재고, 무료분은 손익이 맞는 만큼만 주며(가격보다 무료 한도가 손익을 더 크게 바꾼다), 크레딧은 **덮어쓰지 않는 장부**에 쌓고 서버에서만 뺀다. 돈은 브라우저가 "성공"이라고 말할 때가 아니라 **서버가 발주서(주문)와 대조한 뒤 카드사 승인을 받았을 때** 들어온 것이고, 같은 요청이 두 번 와도 한 번만 처리되게 세 겹으로 막는다.

## 1. 경영 경험으로 풀면

| 오늘 배운 것 | 경영에 빗대면 |
|---|---|
| **메시지 한 건 원가** — 그 안의 LLM 호출 요금 합 | **커피 한 잔의 원재료비.** 내 가게는 평균 약 0.61원인데, 긴 대화의 10번째 이후 메시지는 첫 메시지의 평균 1.42배다 |
| **사용자 유형별 한 달 원가** | **고객별 원가 분석.** 하루 3,000잔 마시는 한 사람이 보통 손님 약 167명분을 쓴다 |
| **무료 한도 vs 가격** | **판촉비와 단가.** 손님 1,000명 중 5%만 산다고 하면(교안 계산기 가정) 단가를 두 배로 올려도 50명만 바뀌지만, 판촉(무료분)은 나머지 950명 모두에게 나간다. 그래서 판촉을 줄이는 쪽이 손익을 더 크게 바꾼다 |
| **크레딧 원장** | **분개장.** 잔액 칸 하나를 고쳐 쓰면 왜 틀어졌는지 모른다. 거래를 한 줄씩 쌓고 잔액은 합계로 낸다. 잘못된 줄은 지우지 않고 역분개한다 |
| **차감은 서버에서만** | **현금은 계산대에서만.** 손님이 영수증(화면)을 고쳐 와도 계산대(서버)의 장부가 기준이다 |
| **결제 인증 vs 승인** | 손님이 카드를 내민 것과 **카드사 승인 문자가 온 것**은 다르다 |
| **금액 비교** | 거래처가 보낸 세금계산서를 **우리 발주서와 대조**한 뒤에 결재한다 |
| **세 곳 기록 대사** | **카드 매출 대사.** 카드사 정산(토스)·판매 전표(주문)·포인트 장부(원장)가 같은지 날마다 맞춘다 |
| **세 겹 장치(주문 상태·원장 참조·멱등키)** | **내부통제 3선.** 현업 확인, 시스템 통제, 거래처 통제. 한 선이 뚫려도 다른 선이 막는다 |

> 💡 **팁** — 비유의 한계: 장부와 결재는 사람이 한 건씩 처리하지만, 서비스에서는 같은 요청이 **거의 동시에 두 번** 오고 연결이 중간에 끊긴다. 그래서 "기록을 잘 남긴다"만으로는 모자라고, 두 요청이 같은 주문을 동시에 읽는 경우까지 막는 장치가 따로 필요했다.

## 2. 오늘 직접 해서 알게 된 것

1. **내 서비스의 원가는 교안 예시의 절반 아래였다.** 최근 7일 실제 91건 평균 약 0.61원, 상위 10% 약 0.73원(교안 예시 1.5원). 작은 모델에 답이 짧아서다.
2. **가장 비싼 단계가 교안과 달랐다.** 교안은 "답 만들기"라 했지만 내 서비스는 **도구 선택이 비용의 42%**였다. 도구 설명 때문에 도구 선택 입력이 처음부터 약 1,000토큰이고, 답은 짧기(출력 평균 36토큰) 때문이다. 대화가 길어진 뒤쪽에서만 답 만들기가 조금 더 비쌌다.
3. **큰 모델은 10개 중 7개에서 나았지만 16.6배 비쌌다.** 모든 호출을 큰 모델로 바꾸면 메시지당 약 10.3원이라, 크레딧 10원에 팔면 **팔수록 손해**다.
4. **무료를 하루 5.5개 넘게 주면 적자였다.** 교안 계산기 식에 내 원가를 넣으니 무료 하루 10개는 약 −16만 원, 3개는 약 +8.7만 원(사용자 1,000명·전환율 5%·고정비 7.5만 원은 교안 가정). 그래서 '하루 무료' 대신 **'가입 때 30개 한 번'**으로 정했다.
5. **결제가 안전 응답을 막으면 안 된다.** 크레딧 0인 사람이 "죽고 싶어"를 보내도 결제 안내 대신 109 안내가 나가게 위기 표현은 크레딧에서 뺐다.
6. **교안과 실제 문서가 달랐다.** 교안의 "문서에 공개된 테스트 키"는 연동 문서에서 사라져 있었고, 토스 공식 샘플 저장소에서 찾았다.
7. **카드사의 본인 확인은 테스트에서도 진짜였다.** 우리카드는 실제 앱, 현대카드는 실제 PIN, 토스페이는 실제 휴대폰 번호를 요구했다. 본인 카드 앱으로 인증하니 승인은 가상으로 났고 세 곳 기록이 맞았다(30 → 130 → 129).
8. **확인 목록 한 줄이 실제 문제를 잡았다.** "서버 로그에 결제 키가 없을 것"을 결제 뒤 검색해 보니, 내 코드가 아니라 웹 서버 접속 기록이 결제 키를 통째로 남기고 있었다.

## 4. 이어 한다면(제안)

1. Cloud Run staging 서비스에 오늘 코드와 결제 키(Secret Manager)를 붙이고(DB 마이그레이션 0002·0003은 시험용 Supabase `friend-agent-staging`에 이미 실행), Cloud Run 앞단 요청 기록에 결제 키가 남는지 확인한다.
2. 요청 속도 제한·하루 상한, 게스트 계정 반복 생성 막기(1장에서 제안한 '로그인 사용자만')를 정한다.
3. 사진 읽기 원가를 재서 추가 차감을 정한다.
4. 오늘 본 품질 실패 셋(이번 달 공휴일 지어냄·약속 답 어긋남·"해줘"에 알림 안 만듦)을 N055 평가 데이터셋에 더한다.
