## 0. 시작 질문 (학습서 1장, 사용자가 직접 씀, 2026-11-04)

> Q. 에이전트 서비스를 무료로 열어 두었더니 사용자 한 명이 하루에 메시지 300개를 보냅니다. 이 사용자 때문에 생기는 문제와, 막으려면 무엇을 정해야 하는지 떠오르는 대로 적어 보세요.

**사용자의 답(원문 그대로)**:

> 한 사용자가 우선 목적에 맞지 않게 300개의 메시지를 개인적인 용도로 사용할 수 있고, 설사 사이트 목적에 맞게 하더라도 다른 사용자가 서비스 받을 수 없을 정도로 토큰이나 리소스를 다 사용해버리면 서비스를 지속적으로 운영할 수 없다. 로그인 사용자만 이용하게 하거나 사용자당 1일 이용갯수를 제한하거나 유료화하는 방안이 있다

**교안과 대어 본 것(8장 회고에서 다시 꺼낼 메모)**:

| 답에 있는 것 | 교안의 어느 장과 이어지나 |
|---|---|
| 목적 외 사용 | 8장 '아직 못 막는 것' — 자동화 악용 계정(하루 3,000개) |
| 토큰·리소스를 다 써서 지속 운영 불가 | 2장 — 원가는 사용자 수가 아니라 사용량에 비례(300개면 보통 사용자의 15배) |

| 유료화 | 3~7장 — 크레딧 묶음 가격, 원장, 결제 |

아직 답에 없는 것(오늘 채울 것): 메시지 한 건이 **실제로 얼마인지**(2장), 무료 한도를 **몇 개로** 둘지 정하는 근거(3장 손익 계산), 돈을 받는 흐름이 **안전한지**(5~7장).

## 2. 메시지 한 건의 원가 (학습서 2장 "직접 확인할 곳: Langfuse에서 원가 표 채우기", 2026-11-04)

**방법**: 화면 대신 Langfuse API로 같은 일을 했다(`실습/확인스크립트/`). 이 SDK(langfuse 5.1.0)에는 트레이스 목록 API가 없어 이름이 `chat-turn`인 **루트 관찰 단위**로 메시지 트레이스를 찾고, 같은 트레이스의 GENERATION 비용을 더했다. 새 관찰 API는 요청한 필드 묶음만 돌려줘 `fields="core,basic,model,usage"`를 붙여야 비용·토큰이 나왔다.

**① 비용 칸이 채워져 있나 (교안 2번)**: 채워져 있다. Langfuse 가격표가 `gpt-4o-mini`를 알고 있어(입력 0.15달러·출력 0.60달러 / 100만 토큰 — 교안의 단가와 같음) **모델 정의(Models)를 따로 추가할 필요가 없었다**.

**② 최근 7일 메시지 비용 (교안 3번, `s1_cost_7days.py`, 원자료 `s1_cost_7days.json`)**: chat-turn 96건 중 generation이 있는 95건, 그중 가짜 LLM이 섞인 4건(비용 0)을 빼고 **실제 91건**(environment: default 45 · local 36 · staging 10, 모두 gpt-4o-mini).

| 값 | 달러 | 원(1,400원/달러 가정) |
|---|---|---|
| 평균 | 0.000435 | 약 0.61원 |
| 중앙값 | 0.000411 | 약 0.58원 |
| 상위 10%(p90) | 0.000519 | 약 0.73원 |
| 최댓값 | 0.000760 | 약 1.06원 |
| 최솟값 | 0.000336 | 약 0.47원 |

- 메시지 한 건의 호출은 **3회**(choose-tools·reply·memory-update)이고, 91건 중 3건은 **4회**였다 — 대화가 쌓이면 `memory-summary`(요약) 호출이 한 번 더 붙는다(그 3건이 0.00067~0.00076달러로 가장 비쌌다). 교안은 호출을 세 가지로만 적는다.
- **가장 비싼 단계가 교안과 다르다.** 교안은 "대개 답 만들기 호출이 가장 비싸다"고 하지만 내 서비스는 **도구 선택(choose-tools)**이 비용의 42.2%(답 만들기 34.4%·기억 정리 21.9%·요약 1.5%)이고 91건 중 67건에서 가장 비쌌다. 도구 선택 입력이 도구 정의 때문에 처음부터 약 1,000토큰이고, 답은 짧아서(출력 평균 36토큰) 출력 단가가 4배라도 답 만들기가 덜 나온다. 대화가 길어지면 뒤집힌다(③).

**③ 긴 대화의 첫 메시지 vs 열 번째 이후 (교안 4번, `s2_long_conversation.py`, 원자료 `s2_long_conversation.json`)**: 최근 기록에는 15턴 넘는 실제 대화가 없어(세션당 최대 11턴 — 그것도 N055 확인 스크립트가 턴마다 새 대화로 보낸 것), **한 대화 안에서 16턴을 실제 LLM으로 보냈다**(로컬, 저장소 메모리, 인사·날씨·고민·공휴일·알림·기억할 정보·앞 대화 참조를 섞음). 16턴 합계 **0.007246달러(약 10원)**.

| 턴 | 메시지 비용(달러) | 답 만들기 입력 토큰 | 도구 선택 입력 토큰 |
|---|---|---|---|
| 1 | 0.000342 | 519 | 988 |

- 답 만들기 입력이 519 → 11턴째 약 1,200토큰까지 늘다가 **그 뒤로 멈췄다** — 교안의 "지난 대화를 최근 10턴까지만 넣으므로 원가는 열 턴 남짓까지 늘다가 멈춘다"와 같다. 도구 선택 입력은 처음부터 끝까지 약 1,100토큰으로 거의 그대로였다.
- 긴 대화 뒤쪽에서는 답 만들기(약 1,200토큰)가 도구 선택(약 1,100토큰)보다 조금 비싸져 교안의 설명에 가까워진다. 이 대화에서는 요약 호출이 붙지 않았다.

## 3. 같은 메시지로 두 모델 비교 (학습서 3장 "직접 확인할 곳: 같은 메시지로 두 모델 비교하기", 2026-11-04)

| 로그인 사용자만 | ✕ 그대로 게스트(익명 로그인)도 쓴다 — 게스트를 새로 만들 때마다 무료 30개를 다시 받을 수 있다(계정당 원가 약 22원에서 멈춤) | 3장 주의 |

**막는 것(사용자 답과 같음)**: 무료분을 다 쓰면 402로 거절되고, 더 쓰려면 사야 한다 — 하루 300개 사용자는 이제 쓴 만큼 낸다(메시지 1개 10원 안팎, 원가 약 0.7원). 원가가 사용량에 비례하는 문제를 가격 구조로 막는다.

**사용자 답에 빠진 것 — 아직 못 막는 것**(해설서 모범 답안 + 실습에서 확인):
- 여러 게스트 계정으로 무료 30개를 반복해서 받는 것(1장의 '로그인 사용자만' 제안이 아직 남은 일)
- 자동화 프로그램의 대량 요청 — 요청 속도 제한(Rate Limit)·하루/월 사용량 상한·동시 실행 수 제한이 없다. 돈을 내는 사용자라도 한꺼번에 몰리면 다른 사용자의 응답이 느려질 수 있다(1장의 '다른 이용자 불편'은 유료화만으로는 다 막히지 않음)
- 예상 밖으로 긴 입력·비싼 기능(사진 읽기)의 원가 — 작업별 최대 토큰·기능별 차감은 보류
- 이상 사용 탐지·알림, 환불·유효기간 정책, Cloud Run 앞단 요청 로그의 결제 키
- 해설서 결론: 원가표는 비용을 파악하고, 크레딧 한도는 비용을 통제하며, 결제 시스템은 정당한 과금과 중복 지급을 막는다. 여기에 비정상 사용 탐지와 요청 제한까지 결합해야 안정적으로 운영된다.

## 12. 기록 보충 — 문서 독립 검증에서 '진행기록에 없다'고 지적된, 대화에서 실제로 있었던 일 (2026-11-04)

문서 4종을 쓴 뒤 독립 검증자가 "진행기록에 없는 일화·인용"을 짚었다. 아래는 이 세션 대화에서 실제로 있었던 일인데 기록에 옮기지 않았던 것이다. 문서는 이 절을 근거로 다시 맞췄다.

## 13. 가장 오래 막힌 곳 (사용자가 직접 씀, 2026-11-04)

**사용자의 말(원문 그대로)**: "결제 테스트를 하는데 막상 카드 값을 입력하려고 했더니 클로드가 막아서 몇 번 그만두고 다시 되풀이하는 장면이 많았어. 퍼실리테이터에게 물어서 결국 진행하고 결과는 좋았어"

- 대응하는 기록: 9절 — Claude는 카드사 창마다 "카드 비밀번호·실제 앱 로그인을 요구하면 멈추라"고 안내했고(우리카드·토스페이·현대카드에서 세 번 멈춤), 현대카드 화면에서 "문서용 테스트 키로는 실제 비밀번호나 앱 인증 없이 승인까지 가기 어렵다"고 좁게 말해 '여기까지만 확인'을 권했다. 사용자가 "정상적으로 승인이 나는 것은 볼 수 없는 거야?"라고 물은 뒤에야 본인 카드 앱 인증으로 진행했다.
- 새로 안 사실: 사용자는 그 사이 **퍼실리테이터에게 물어** 진행하기로 했다(이 대화에는 없던 일 — 사용자의 말이 근거).
- Claude 쪽 교훈 후보: 결제·개인정보 앞에서 멈추라는 안전 안내는 맞지만, "테스트 환경에서는 카드사 인증 뒤 승인이 가상"이라는 사실을 처음부터 함께 말했으면 되풀이가 줄었다. 안전 경계(Claude는 카드 정보를 입력하지 않음)와 사용자가 스스로 할 수 있는 일(본인 앱 인증)을 처음에 나눠 말한다.
