# N036 실전 적용 리포트 — 스토리형 콘텐츠 산업 뉴스레터 에이전트

> N036 강의의 5단계 파이프라인(수집→선별→요약→검수→발행)을 실제 관심사(스토리형 콘텐츠 산업
> 뉴스 + 연계 채용·정부지원사업)에 적용해, Colab에서 실제로 Discord 채널까지 발행한 기록입니다.
> 실행일: 2026-09-14. 노트북: [`newsletter_agent_full_colab.ipynb`](./newsletter_agent_full_colab.ipynb)

## 핵심 요약
3개 트랙(콘텐츠산업뉴스/채용/지원사업)에서 실제 뉴스 66건을 수집해 최종 6건을 Discord에
발행하기까지, 과정에서 실제 문제 두 가지(같은 사건 중복 선정, 오래된 기사 유입)를 만났고
그중 하나는 뒤에 있던 다른 관문이 자동으로 막아내는 것까지 확인했습니다.

## 무엇을 만들었나
| 트랙 | 검색어 | 등급(Score) 기준 | 마감일 관문 |
|---|---|---|---|
| 콘텐츠산업뉴스 | 웹툰 산업, 웹소설 시장, 숏폼 드라마, OTT 드라마 제작 | 구체적 수치·계약·편성·투자 변화 우선 | 없음 |
| 채용 | 웹툰 웹소설 채용, 콘텐츠 기획 채용, 숏폼 PD 채용, 드라마 제작 채용 | 스토리형 콘텐츠 직무 관련도 | 있음 |
| 지원사업 | 웹툰 웹소설 지원사업, 콘텐츠 창작 지원사업, 문화체육관광부 콘텐츠 공모 | 실제 신청 가능성 | 있음 |

수집은 Google 뉴스 검색(RSS)으로, 발행은 Discord 웹훅으로 했습니다. API 키·웹훅 URL은
전부 Colab 보안 비밀로만 관리했습니다(코드에 직접 적지 않음).

## 단계별 실행 결과

### 1~3단계 — 수집·URL 해석·G1 관문
| 트랙 | 수집 | G1 관문 통과 |
|---|---|---|
| 콘텐츠산업뉴스 | 24건 | 20건 (83%) |
| 채용 | 24건 | 21건 (88%) |
| 지원사업 | 18건 | 14건 (78%) |

**실제로 만난 문제**: Google 뉴스 RSS의 링크는 진짜 기사 주소가 아니라 자바스크립트
리다이렉트 래퍼였습니다. `trafilatura`로 그대로 열면 항상 실패해서, `googlenewsdecoder`로
실제 기사 URL을 먼저 풀어낸 뒤에만 본문을 추출하도록 고쳤습니다(사전 테스트로 확인 후 반영).

G1 관문을 통과하지 못한 나머지는 접속 시간초과(예: `m.dculture.news`)나 접근 차단
(403, 예: `kukinews.com`)이 원인이었습니다 — N036 챕터5의 "소스별 실패 격리"대로, 이런
실패는 조용히 넘기지 않고 관문 미통과로 처리되어 전체 실행에는 영향을 주지 않았습니다.

### 4단계 — 선별(Score, 트랙 내 전체 비교)
각 트랙 상위 4건씩, 총 12건 선정.

**실제로 만난 문제**: 지원사업 트랙에서 같은 사건("2026 서울테마 웹소설·웹툰 제작지원",
5억 원 규모)을 다룬 기사 2건(헤럴드경제·에이빙)이 동시에 상위 4건에 들었습니다. 선별
프롬프트에 "같은 사건은 하나만 높게 평가하라"고 명시했는데도 지켜지지 않았습니다 — N036
챕터7·8이 반복해서 경고한 "프롬프트는 요청이지 보장이 아니다"가 그대로 재현된 사례입니다.
이번엔 사용자가 직접 하나를 제외하는 대신 "그냥 진행"을 택했고(피해가 크지 않은 경우),
근본적으로 고치려면 N036 챕터7의 `event` 라벨 + `Counter` 재검증 패턴을 선별 단계에도
적용해야 합니다(다음 개선 과제로 남김).

### 5~6단계 — 요약(스키마 분리) + LangGraph Send 팬아웃
- 선택 12건 → 취재 완료 12건 (실패 0건)
- 12건 모두 첫 시도에서 `headline`·`summary` 필드별 한글 검사를 통과(재시도 0회) — 챕터8
  실습 때와 달리 이번 12건은 전부 한 번에 한국어로 나왔습니다.

### 7단계 — 검수(마감일 형식·경과 확인, 채용·지원사업만)
| 결과 | 건수 |
|---|---|
| 마감 지남 → 발행 제외 | 6건 (전부 2023~2024년 날짜) |
| 마감일 확인 필요(본문에 명시 없음) → 발행 유지 | 2건 |
| 콘텐츠산업뉴스(관문 대상 아님) | 4건 |
| **최종 발행 대상** | **6 / 12건** |

**가장 중요한 발견**: 마감 지난 6건이 전부 오래된(2023~2024) 기사였습니다. 원인을
역추적하니, **수집(1단계)에 "게시일이 최근인가" 필터가 빠져 있었습니다** — Google 뉴스
검색은 키워드만 맞으면 연례 반복 사업명("OO 제작지원" 같은) 등 오래된 기사도 섞어
반환합니다. 그 결과 오래된 기사가 수집→G1 관문(본문은 있으니 통과)→선별(제목이
관련 있어 보이니 선정)까지 올라왔지만, **마지막 마감일 검증 관문이 정확히 걸러냈습니다.**
즉 앞 단계의 구멍(게시일 필터 부재)을 뒤 단계(마감일 검증)가 방어한, 다층 검증이 실제로
작동한 사례입니다. 다음 버전에서는 수집 단계에 게시일 필터를 추가해 애초에 오래된 기사가
API 호출까지 가지 않도록 개선할 수 있습니다.

### 8단계 — 발행(Discord)
`DRY_RUN=True`로 먼저 6개 embed 구성을 확인한 뒤, `DRY_RUN=False`로 전환해 실제 발행.
**응답 코드 204(성공)** 확인.

**최종 발행된 6건**
1. [콘텐츠산업뉴스] 웹툰 산업, 창작자 신뢰 기반으로 지속가능한 생태계 구축 필요
2. [콘텐츠산업뉴스] 웹툰·웹소설 플랫폼 서비스 종료와 소비자 권리
3. [콘텐츠산업뉴스] 울산, 게임·웹툰·영상 융합 콘텐츠 협업 IP 개발 나선다
4. [콘텐츠산업뉴스] MBC, 숏폼 이어 미드폼 드라마 제작 계획 발표
5. [채용] 윗유(witU), '숏폼 커머스 급성장' 대규모 공개채용 *(마감일 확인 필요 — 직접 확인 권장)*
6. [지원사업] 카카오창작재단, K인디와 웹툰·웹소설 창작자 지원 확대 *(마감일 확인 필요 — 직접 확인 권장)*

## 다음 개선 아이디어
1. **수집 단계에 게시일(recency) 필터 추가** — `published` 필드를 활용해 N일 이내 기사만
   통과시키면, 이번에 발견한 "오래된 기사 유입" 문제를 애초에 예방하고 API 호출도 절약됩니다.
2. **선별 단계에 event 라벨 + Counter 재검증 추가** — N036 챕터7 패턴을 그대로 가져와, 같은
   사건 중복 선정을 프롬프트 지시만이 아니라 코드로도 막습니다.
3. **정기 자동 실행 검토** — 지금은 수동 실행(Colab 더블 실행)이며, 필요해지면 N036
   챕터11처럼 GitHub Actions cron으로 자동화할 수 있습니다(현재는 계획에 없음).

## 결론
N036에서 배운 원칙(관문/등급 분리, 필드별 검증, dry-run 안전장치, 실패 격리)이 실제
운영 데이터(오래된 기사, 중복 사건, 접속 실패)에서도 그대로 작동했습니다. 특히 "관문 하나가
뚫려도 뒤에 있는 다른 관문이 막아준다"는 다층 방어가 설계가 아니라 실행으로 실제 확인된
것이 이번 실습의 가장 큰 성과입니다.
